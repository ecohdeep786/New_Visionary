# API v1 preparation — KAN-30

This is an executable **draft enabler**, not a registered API or authorization service. `manifest.json` records `frozen: false` and zero registered endpoints. KAN-29 source decisions, KAN-31 authority acceptance and KAN-32 admission/policy acceptance remain freeze gates. New domain wiring must wait. Existing auth, account, billing, feedback and learning routes retain their paths, cookies, parsers, response shapes and behavior.

`definitions.mjs` is the source for JSON Schema 2020-12 `schemas.json`, OpenAPI 3.1.1 `openapi.json` and the legacy compatibility/operation manifest. `validate.mjs` compiles every definition with pinned Ajv 2020, formats and strict validation. It accepts serialized JSON, checks the entire UTF-8 body and KAN-35 structural limits, then validates fields without coercion, trimming, defaults or field removal. Text limits count Unicode scalar values and reject lone surrogates. Schemas are deliberately bounded and closed to unknown fields; references are identifiers, never permissions.

Run in this directory with Node 22–24:

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm run build
npm run check
npm audit --omit=dev --audit-level=high
```

Root `npm run check` includes contract drift and boundary tests; CI installs this independent lock first. Generator outputs are checked byte-for-byte. No backend, frontend or ML module imports this package. To recover from a draft regression, revert the task commit; there are no migrations or persistent product changes.

## Contract semantics and unresolved integration

- Mutation identity is `mutationId`; the draft fingerprint includes the DTO name, workspace, policy, expected revision, target and body. Sorted JSON object keys make key order irrelevant; arrays and exact text retain their meaning. This is an internal comparison convention, not RFC 8785 or an authorization token. Future servers must scope command storage by authenticated actor/workspace and mutation identity, reauthorize every replay, and atomically compare/store canonical command hashes with receipts. `same-payload` does not authorize returning a prior result.
- Revision comparison is a pure helper, not a database transaction. Build's strong `If-Match` and body expected revision must agree; stale ETag uses 412, changed command or expected-account mismatch uses 409. This explicitly reconciles Build's documented 412 contract with KAN-35's earlier proposed combined 409. Other domain revision/error mappings remain draft until authority review. Preserve the browser draft, then read authorized durable status on uncertain writes; do not blindly retry paid work.
- The OpenAPI paths describe proposed routes only. Project path and body IDs must agree; future adapters must perform that cross-field check. Responses distinguish durable acceptance (202) from an owning-store committed receipt. A pending projection is not synchronized success. A proposal, final transcript, complete event or cancellation acknowledgment is never proof of a domain commit. `CommitReceipt` syntax alone does not prove a transaction occurred.
- Current HTTPS authentication uses both `__Host-visionary-session` and `__Host-visionary-device` cookies. Loopback drops `__Host-`. Mutations require the exact allowed Origin and `X-CSRF-Token` matching the CSRF cookie; `X-Visionary-Account` is a compared hint. OpenAPI security declares session/device/header together; cookie pairing and Origin validation remain server responsibilities. This package does not replace current Firebase authority with caller-supplied UID, role, workspace membership or preview capabilities.
- Cursor syntax is bounded to 512 ASCII bytes. Issuance, signature, expiry and binding to UID/workspace/query/order/current policy are unimplemented. Pagination defaults to 20 at the eventual adapter, capped at 50 plus whole-response bytes; this validator does not insert defaults. Expired cursors require authorized refetch. Legacy cursor formats remain untouched. Change events carry invalidation references, not private resource bodies.
- Stream events reserve KAN-35 framing bytes; aggregation, backpressure, event count, total bytes, idle/deadline timers and actual downstream cancellation are future runtime gates. Partial output remains an uncommitted draft. Oversized generated output yields unavailable, not a client-input 413. Voice chunks contain private media references, never inline audio; transcript DTOs cannot validate as action commands. Human confirmation, permitted voice media/size, session ownership and consent must be enforced by a future adapter.
- File metadata does not approve MIME/size or mint URLs. Private quarantine, digest/size/MIME scan and current owner authorization precede finalize. Pack manifests reference approved versioned sources; a valid date or digest shape does not establish provenance or expiry. Offline replay rechecks current authority/consent/source/policy and each command identity; revoked packs cannot grant access. This package provides no cached permission or offline commit authority.
- Stage/profile/mapping/receipt and coaching/summary DTOs are bounded draft shapes from the lifelong contract. `relatedReceiptId` is required for undo/postpone; exact per-action admission awaits source/authority review. One owning profile authority must commit a new revision plus receipt/outbox atomically; account projections cannot become a second authority. No automatic stage promotion, reset of onboarding history, snapshot restore over later work or inference-as-approval. Postpone/undo windows (7/14 days) and exact current revision checks remain owning-server responsibilities. Summary audience/purpose/relationship/consent/source revisions are checked against current authority; raw private doubts and public coaching visibility are rejected by shape.

All fixtures are synthetic. Shape-denial tests for forged actor/role fields are not wrong-user/workspace/consent authorization tests. Those require connected server/store and two-device/hosted evidence under the linked gates. Source licensing, provider privacy, entitlements, quotas, official syllabus, signed cursors and release acceptance remain open. No passing schema test closes them.
