# Contracts to reconcile before live cutover

Updated15 October2026, D-075. These are observed current integration boundaries, not newly implemented APIs. The founder authorized backend/ML work; the [source audit](../docs/architecture/discussions/backend-ml-audit.md) and [100,000-MAU design](../docs/architecture/discussions/system-design.md) now guide the next slices.

16 October2026, D-082: [account feedback v1](FEEDBACK_CONTRACT.md) is now implemented in the product runtime and connected frontend control. It uses verified UID-owned Firestore records; it does not connect the legacy ML feedback handler, grant operator access or complete the remaining support/privacy/hosted gates. The [execution handoff](../docs/architecture/IMPLEMENTATION_HANDOFF.md) records the fresh backend/ML review and next dependencies.

Firebase Authentication, verified server/device sessions, profile/onboarding and canonical UID-owned Firestore account storage are connected locally. Razorpay test billing, invoices and Family billing benefits are connected through the same product runtime. See [auth](FIREBASE_AUTH_CONTRACT.md), [billing](PAYMENTS_CONTRACT.md) and [account storage](USER_ACCOUNT_STORAGE.md) for actual evidence and remaining hosted/provider gates. The old JWT/Prisma application remains an imported reference, not the current identity runtime.

| Boundary | Product contract | Current implementation | Remaining integration work |
| --- | --- | --- | --- |
| Account session | One UID across devices; verified session and owner-bound account | Firebase ID-token exchange, secure bound device cookies, account/profile/session endpoints | Hosted cookie/proxy/recovery acceptance; server-owned workspace membership and role policy |
| Sign-in consumer | Async loading/error and account-switch isolation | Connected asynchronous auth and stale-response handling; local/emulator regression evidence | Retain behavior when domain/model adapters are connected; do not reintroduce the historical Promise bug |
| Onboarding | Five-role preferences and independent language/context | Validated UID-owned setup persisted in Firestore | Role selection is not verified organization/guardian membership; implement those workflows separately |
| Billing and account records | Auth-required checkout; Free default; immutable private invoices | Current test subscriptions, durable reconciliation and UID-tree account/device/invoice APIs | Actual hosted test webhook/provider acceptance; growth outbox/Tasks; live commercial/tax gates |
| Organization and parent access | Current role, membership, teacher ownership, child consent scope/expiry | No complete matching membership/relationship/consent schema in imported Prisma source | Server-side authorization and immutable audit/history; protect every list/get/write/export |
| Content catalog | Validated `ContentGraph`, book/chapter/topic/concept IDs, version, provenance, authored language/representations | Subject/book/chapter/topic records and tracking endpoints | Map stable IDs and source versions; learner-safe authored DTOs; unsupported/unavailable states |
| Teaching | `teaching.request` returns ready/not_connected/blocked, text, locale, prompt version and optional validated activities/representations | NestJS direct-provider content/diagram/resource orchestration and chat SSE | Product-owned prompt/context contract, source review, safety behavior and response validation |
| ML gateway | Only backend-authorized person/workspace/source context should enter ML | Go `/api/v1/query`: query/session_id/grade/subject/stream; JWT user claim; answer/sources and optional grounding fields | Server-to-service identity, audience and source restrictions, user/workspace/session reconciliation and output adapter |
| Mentor | `mentor.turn`, matching locale/context version, role-permitted action IDs | No matching NestJS or RAG endpoint | Typed product operation; allowed actions owned by server policy; explicit disconnected behavior |
| Caching and memory | Data partitioned by person/workspace and source/version; revoked access must stop pending output | RAG response-cache key uses query/sessionContext/grade/subject | Inspect all cache layers; scope protected content to authority/source revisions and verify invalidation/revocation |
| Deadlines and streaming | Client exchange defaults to 20s for the whole operation; caller cancellation | RAG gateway defaults include a 120s total request deadline; NestJS chat stream has another shape | Reconcile deadlines, SSE parsing, cancellation, bounded output, disconnect cleanup and partial-response policy |
| Persistence and conflict | Expected revisions, retained draft recovery, private versus submitted artifacts | Application user/content/chat/tracking schema; retrieval database has a separate schema | Transactions, owner-scoped DTOs, idempotency keys, trusted timestamps and durable revision semantics |
| Database connections | Account/billing durable; learning largely local | Current Firebase product runtime does not require old Prisma/Redis/model startup | New SQL domain schema/pools/outbox; retain Firestore account/billing authority; no automatic old migrate/seed |
| Optional providers | Model failure must not disable account/payment | Connected product module graph excludes legacy eager agents/Google strategy | Preserve separation when introducing private AI; explicit provider availability and graceful degradation |
| Research tooling | No runtime dependency on inspection tools | REA local CLI/MCP; optional native providers | Keep analysis separate from production; evidence-backed requirements, independent implementations |

Implementation order: workspace/consent authority and SQL provisioning -> one authorized content/teaching operation with durable learning -> evaluated private AI -> hosted payment/queue/recovery acceptance -> linked-role expansion. Keep browser originals until a reviewed owner-confirmed migration succeeds. Similar field names or successful builds are not interoperability tests. Root `backend:dev`/`backend:start` now select the connected product entrypoint; old package startup/Docker defaults must not be used.
