## Goal
Refine the existing landing page into a more coherent Apple × Google education product experience without changing the approved content model or creating a new page.

## What the reference audit found
- Apple Education establishes a strong chapter rhythm: one clear headline, one supporting thought, one dominant visual, and a small number of actions. Visuals are full-bleed or deliberately framed, with generous whitespace and very little simultaneous UI.
- Google for Education combines a compact global header with role/product navigation, then uses modular product sections, tabs, carousels, and accordions to progressively reveal detail. Mobile patterns collapse navigation and preserve horizontal discovery rather than squeezing desktop layouts.
- The current page already has the correct brand ingredients, but the landing route layers many moving systems together: autoplay text, sticky audience tabs, scroll-driven phases, multiple carousels, oversized desktop gaps, and a large mega-menu. The five-person hero lineup also has a likely narrow-screen overflow risk because its minimum widths plus gaps exceed a 320px viewport.

## Implementation plan

### 1. Establish one responsive layout contract
- Update the shared public spacing/type bridge so all landing chapters use the same max-width, side-gutter, section spacing, media radius, and mobile safe-area rules.
- Add explicit narrow-width rules for 320–390px screens: clamp chapter padding, prevent horizontal overflow, normalize heading line lengths, and keep buttons full-width or comfortably stacked where necessary.
- Preserve the existing Google Sans Flex and accent-gradient system; remove only contradictory overrides.

### 2. Rework the global landing navigation
- Keep the current routes and menu content, but make the desktop header quieter and more Apple-like: compact nav height, predictable max-width, smaller menu surface, and one obvious primary action.
- Make the mobile drawer feel like a first-class responsive navigation state: clear section separators, safe-area padding, no accidental body scroll, and a compact top utility row.
- Add focus/escape behavior and ensure menus close cleanly on viewport changes and route transitions.

### 3. Refine the hero for real device widths
- Keep the existing five-person product visual and approved copy, but make the lineup use responsive image sources and a width model that mathematically fits 320px through wide desktop.
- Reduce the hero’s vertical dependency on `vh`, keep a hint of the following chapter visible on mobile, and make CTA stacking intentional below the small breakpoint.
- Respect reduced motion by disabling floating/blur entrance behavior while keeping content immediately visible.

### 4. Simplify chapter composition around one focal point
- Rebalance the Problem, Meet, Commitment, Trust, CTA, Explore, and FAQ chapters so each has a clear visual hierarchy: eyebrow, display statement, supporting copy, then one interaction or media focal point.
- Preserve the existing interactions, but reduce competing simultaneous animations and avoid autoplay where it makes reading/navigation unstable. User selection remains primary; autoplay becomes paused or reduced on reduced-motion and small screens.
- Replace desktop-only spacing assumptions such as very large viewport-relative gaps with bounded responsive values.
- Keep horizontal card discovery for Explore/Trust, but make the first card, scroll affordance, and keyboard/focus states explicit on mobile.

### 5. Make the dark “One Intelligence” chapter resilient
- Keep the chapter’s scroll-driven desktop storytelling, but provide a simpler mobile sequence with stable intrinsic heights and no reliance on sticky positioning for the core message.
- Ensure the window, phase labels, progress line, and closing statement fit without clipping at 320px/390px widths.
- Respect reduced motion and avoid background/glow treatments that compete with the product window.

### 6. Verify behavior at representative viewports
- Run lint, typecheck, and production build.
- Start Vite and inspect the landing route at 320×800, 390×844, 768×1024, 1280×720, and 1440×900.
- Check hero overflow, fixed-header offsets, menu/drawer behavior, section transitions, sticky tabs, carousels, FAQ focus states, image loading, and reduced-motion behavior.
- Fix any visual or interaction regressions found during the pass, then report the local URL and validation results.
