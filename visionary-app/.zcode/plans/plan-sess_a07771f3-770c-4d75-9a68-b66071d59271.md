## Apple-grade public page convergence plan

### 1. Establish one shared visual contract
Update the shared public styles so every public page inherits the same Apple-like laws:
- White, full-width chapter bands with no stacked rounded section containers.
- Consistent section rhythm derived from the existing `--breath-section` and `--frame-x` tokens.
- Apple typography hierarchy: restrained sentence-case lead-ins, display headings with tight tracking, near-ink body text, and one accent-gradient phrase per chapter.
- Restrained media radii and hairline borders; remove page-level rounded-tops and heavy pill/card treatment where it makes chapters feel like separate dashboards.
- One deliberate dark cinematic chapter for the intelligence/story section, matching the existing premium motion system.
- Responsive rules for narrow mobile screens, large desktop gutters, image sizing, and no horizontal overflow.

### 2. Upgrade shared persona-section architecture
Refine `src/components/landing/persona/PersonaSections.jsx` so duplicated Student/Teacher/Parent/College/Organization content uses a common premium anatomy:
- Struggle/problem chapter: editorial two-column composition with stable media sizing and no decorative over-chrome.
- Journey carousel: flatter Apple-style media rails, consistent controls, and accessible labels.
- Intelligence visual: a shared dark or high-contrast product chapter that gives the page one cinematic change of mode.
- Continuity and achievement modules: use open layouts and clear hierarchy instead of nested card stacks.
- Trust and CTA modules: consistent button treatment, content width, spacing, and responsive behavior.
- Fix existing shared accessibility defects such as the malformed carousel `aria-label` string.

### 3. Apply the contract to each target page
Update only the page-level differences needed for the content to fit the shared system:
- `StudentPage.jsx`: preserve student-specific journey, achievement, language, and CTA content while adopting the shared chapter classes and visual rhythm.
- `TeacherPage.jsx`: same shared architecture with teacher-specific instructional content.
- `CollegePage.jsx`: normalize its older professional/college layout to the same white/dark chapter rhythm and responsive media contract.
- `ParentPage.jsx`: align family/progress sections with the same media rail, trust, and CTA patterns.
- `OrganizationPage.jsx`: preserve organization contexts and sales CTA while adopting the same chapter architecture.
- `Landing.jsx`: keep the five-person Apple family hero, then make the following chapters feel like the same product system instead of a separate Google-style page.

### 4. Keep route and content behavior stable
- Do not change route paths, copy meaning, CTA destinations, data models, or modal behavior.
- Preserve existing reduced-motion behavior and add any missing gates in shared animation rules.
- Leave unrelated dashboard and worktree changes untouched.

### 5. Verify the full public matrix
- Run `npm run build`.
- Use the local browser to inspect `/`, `/student`, `/teacher`, `/college`, `/parent`, and `/organization` at desktop, tablet, and mobile widths.
- Check first viewport, chapter transitions, media crops, carousels, modals, CTA routes, keyboard focus, reduced motion, and horizontal overflow.
- Run focused tests or lint checks available in `package.json` and report any unrelated failures separately.

Expected primary files: `src/styles/public-system.css`, `src/styles/public-bridge.css`, `src/styles/premium.css`, `src/components/landing/persona/PersonaSections.jsx`, and the six target page files only where shared classes or section wrappers must change.
