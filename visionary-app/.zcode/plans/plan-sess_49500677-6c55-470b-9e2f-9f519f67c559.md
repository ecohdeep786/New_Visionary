## Product outcome
Build a new Visionary public product language born from Google Education's system clarity and Apple's editorial/product storytelling. The result will use one coherent visual grammar across the homepage, persona routes, supporting public routes, auth shell, and shared landing components while keeping existing routes, content intent, accessibility, and product behavior intact.

## Design decisions
- **Google layer:** one sans system, restrained blue accent, 16px/24px body, 18-20px/28px support copy, 28-36px section headings, 48-64px major headings, 80px hero display, 1120-1240px content frames, 72-88px desktop gutters, quiet borders, accessible controls, utility navigation.
- **Apple layer:** product-first imagery, literal headlines, one dominant visual per chapter, deliberate 144px desktop and 112px mobile spacing, alternating white/soft-neutral/black bands only for major narrative chapters, sparse copy, controlled motion.
- **Visionary layer:** white/ink/blue identity, real learner imagery, continuity and memory as the product story, persona-specific copy, no imitation of either brand's logo or proprietary UI.

## Implementation stages
1. **Canonical public tokens and primitives**
   - Consolidate `rhythm.css`, `index.css`, and Tailwind-facing conventions into one canonical public contract for type, frame, section spacing, bands, radii, borders, elevations, buttons, focus, and motion.
   - Add shared landing primitives for shell/frame, section intro, primary/secondary actions, media chapters, editorial bands, tabs, rails, and FAQ/trust surfaces.
   - Keep reduced-motion and Indic-language behavior intact.

2. **Shared navigation and footer**
   - Refactor `LandingNav` and `LandingFooter` to consume the contract, align to the same frame as page content, and use one dropdown, button, utility, and mobile drawer treatment.
   - Preserve current information architecture and route destinations.
   - Verify keyboard focus, Escape/outside-close, route changes, mobile scroll lock, and anchor offsets.

3. **One persona product template**
   - Extract the repeated Student/Teacher/Parent/Professional/Organization chapter structure into a data-driven shared template.
   - Keep persona-specific copy/images/data while unifying hero, problem, promise, journey, intelligence, continuity, achievement, language/trust, CTA, explore, and modal/accordion patterns.
   - Remove oversized/inconsistent radii, nested decorative cards, ad hoc type scales, duplicated spacing, and competing animation systems.

4. **Homepage recomposition**
   - Rebuild `Landing.jsx` around the same chapter grammar, retaining the strongest existing interactions but simplifying their visual treatment.
   - Make the universal hero product-first and responsive, ensure the next chapter remains visible, and apply Apple-style bands only where narrative separation helps.
   - Use Google-style flat treatment for explanatory, language, trust, FAQ, and utility chapters.

5. **Supporting public routes**
   - Migrate `how-it-works`, organization/program pages, download, about, pricing, careers, research, community, contact, partners, updates, referral, safety, privacy, security, accessibility, terms, and cookies to shared compositions: product story, audience/program, editorial index/detail, conversion, and trust/legal.
   - Preserve content and routes while removing one-off page shells and inconsistent layout rules.

6. **Auth/shared boundary**
   - Apply the public contract's global type, color, focus, and spacing foundations to auth pages and shared product shell without altering dashboard workflows or claiming an unauthenticated dashboard visual audit.
   - Keep seeded-session dashboard QA explicitly separate.

7. **Verification**
   - Run `npm run lint`, `npm run typecheck`, and `npm run build`.
   - Start Vite and test representative routes at 1440px, 1280px, 390px, and a short laptop viewport.
   - Check overflow, hero clipping, heading fit, image loading, anchors, focus, reduced motion, and chapter rhythm.
   - Render screenshots for representative homepage, persona, editorial, legal, and auth pages; perform visual acceptance and repair issues before completion.

## Scope discipline
Expected changes are limited to `src/styles`, shared landing components, shared persona/template code, `src/pages/Landing.jsx`, public landing route files, and auth shell styling where needed. Existing user modifications will be preserved and incorporated; dashboard services and unrelated product logic will not be rewritten.
