** Break connection of work Prompt**


INCIDENT FREEZE. A council/weekly run damaged the frontend. Run no daily/weekly loop until clear.
1. STOP: in council/DIRECTOR.md set ACTIVE_AGENT=none, PHASE=ABORTED, CURSOR=none; append an
   INCIDENT header to ../STATUS.md with timestamp + symptom (blank page / wrong layout / lost
   image / red gate / spec file edited w/o DECISIONS / trade-dress clone / MATCH region changed).
2. LOCATE: git status + git log --oneline -20 since last week-* (or week-baseline). If unclear,
   git bisect start HEAD <last-green-tag> with scripts-tmp/final-verify.mjs as the bisect run
   script (good=exit 0).
3. RESTORE to last known green WITHOUT losing unrelated good work: prefer git revert <bad-commit>
   (keeps history, reversible) over reset. If the break is uncommitted working-tree damage,
   git stash the bad edits, then git checkout <last-green-tag> -- <affected paths> to restore
   only those. NEVER git reset --hard a tag unless the founder confirms discarding the week.
4. RE-GATE: rebuild (vite build) + run scripts-tmp/l0-audit.mjs + final-verify.mjs + rhythm.mjs +
   composition.mjs + motion-static.mjs across all routes × 360/768/1440/1920. Must be fully green
   (G1–G10 + R1–R5 + L3 + L7 + L8 + G-REF-*) before proceeding.
5. RE-SNAPSHOT: node scripts-tmp/manifest.mjs --snapshot so DETECT's baseline matches the restored
   tree (otherwise the next run mislabels the restore as a founder edit).

   the tightened guard), and hand back to the daily loop. Confirm to the founder in one line:
   restored-to=<tag>, gate=green, root-cause=<one clause>, guard=<one clause>.
