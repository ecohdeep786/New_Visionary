**This is a target delivery contract, not a claim that the listed APIs, tables, streams or models are connected.** Keep current Firebase UID/account/test billing/feedback behavior. Each ticket has one enabler/feature scope and linked integration acceptance; a frontend preview or passing unit test cannot close a hosted feature.

## Shared completion contract

- **frontend:** Preserve the current route/facade, accessibility and released locale/category/role behavior. Runtime-validate DTOs; show loading/empty/partial/denied/revoked/conflict/unavailable/retry honestly and preserve recoverable drafts.
- **api:** Versioned command/query schema, bounded JSON/files, errors/cursors and timeout; stable mutation ID plus payload digest; conditional revision; no automatic retry with a new command ID after ambiguous commit.
- **authority:** Verified Firebase UID/session/device, expected account and mutation Origin/CSRF; server-derived workspace membership, purpose/consent/source policy. IDs and events locate data but never grant permission.
- **database:** One authoritative store per invariant. Firestore owns account/billing; PostgreSQL owns domain/membership/evidence/run state, linked by the same UID. Private objects hold bytes. Cross-store effects use durable idempotent reconciliation, not an assumed distributed transaction.
- **jobs:** When asynchronous: owning-store outbox, private task identity, leases/fencing, bounded retries/deadline, cancellation, restart/ack recovery and exactly one accepted completion. Mark no-job operations explicitly; never add queues just for a diagram.
- **cache:** Default to no shared private-response cache. If enabled: UID/workspace/policy/resource/source/model/locale versioned key as applicable, bounded entries, reauthorization/invalidation and cache-down fallback. CDN only for approved public assets. Cache expiry is not permission or a record-retention policy.
- **realtime:** HTTPS commands remain authoritative. Durable ordered change/run events are observations; bounded polling baseline and SSE where required. Define auth/connect/reconnect/output checks, heartbeat/backoff/backpressure, duplicate/gap/cursor-expiry handling, refetch and two-device convergence. WebSocket requires reviewed bidirectional need; current browser storage events are local only.
- **ml:** Only explicitly allowed tasks call the private model/tool adapter. Pin input/source/prompt/model/tool versions, bounded usage and scoped memory; validate output/citations/outcomes and recheck permission before delivery/acceptance. No ML involvement is a valid explicit choice.
- **entitlements:** Server checks current feature entitlement and fleet/UID/workspace admission before expensive work. Unique usage reservation/ledger/settlement; plans/Family benefits never confer educational or organization authority.
- **operations:** Per-feature redacted correlation traces, latency/error/queue/unit-cost metrics, quota limits and failure diagnosis; schema/config compatibility, backups/restore, canary/rollback and named launch acceptance. No raw private prompt/payment context in routine telemetry.
- **acceptance:** Meaningful UI→real API→authoritative store→read/resume tests; two devices where state persists, wrong actor/workspace/source/consent denial, concurrency/idempotency, disconnect/restart and dependency outages. Attach exact change, environment, tests/results and rollout evidence; local fixtures cannot close hosted/provider gates.

All five roles, released learner categories and interface/source/output languages must be enumerated under SCOPE-01/02 and ACCEPT-05. Current unsupported age/modalities/provider combinations stay unavailable. The following 18 feature families map the current App routes; controls, embedded panels, redirects and newly added routes still require the executable inventory before launch.

## Feature tree

```text
User/device → existing frontend route/facade → HTTPS API/schema
  → verified UID/session → workspace/object/consent/source/entitlement policy
  → idempotent command + conditional revision → authoritative store
      ├─ Firestore: account/onboarding/devices/billing/feedback
      ├─ SQL: workspace/source/learning/classroom/Build/evidence/run state
      ├─ Private objects: immutable content/assets/export bytes
      └─ Owning-store outbox → private bounded jobs / ML workflow
          → allowed retrieval/tools → candidate validation → policy recheck
  → committed result + durable observation cursor
  → polling/SSE (WebSocket only when needed) → scoped invalidate/refetch
  → second device resumes authorized committed state
  → optional minimized feedback → reviewed evaluation/improvement
```

## Dependency meaning and completion

There are 133 task-level prerequisite edges in addition to the 30 phase edges. Native Blocks represents prerequisite-to-dependent acceptance, not a ban on preparatory design. Other feature-ticket cross-links are context, not invented circular blockers. A task may satisfy a scoped enabler while its connected feature remains open. Existing Done tasks retain their historical local limits; the trace does not retroactively certify them.

Commit and observation are separate: an HTTP command commits to its owning store; only then is an outbox/change event eligible for delivery. Reconnect refetches current authorized state. Revisions prevent stale overwrites, scoped sequence cursors detect gaps, and current policy gates output. Firestore↔SQL has no atomic distributed transaction; durable handoffs reconcile by UID and command identity. Socket disconnection does not imply command failure or justify repeating a charge/submission with a new key.

Server cache is optional at launch. Existing frontend query caching still requires exact scope/invalidation/account-switch tests. Cache-down mode queries the canonical store under admission limits. Never cache private results in the public CDN or allow cached consent/entitlement to authorize a protected action. No retention/deletion change is made here.

## AGI ambition and measurable capability

For Visionary, the working engineering interpretation is a system that helps users learn, reason, plan, use permitted tools, build artifacts, remember approved context and improve across tasks. This is an interpretation of the founder’s product direction, not a redefinition or proof of AGI. Software integration is one scorecard; cognitive capability, generalization and autonomy are separate scorecards. Hold thresholds and released task families in AI-13 before accepting results.

Google DeepMind separates performance, generality and autonomy in [Levels of AGI](https://deepmind.google/research/publications/66938/). Its newer [cognitive evaluation framework](https://blog.google/innovation-and-ai/models-and-research/google-deepmind/measuring-agi-cognitive-framework/) proposes held-out cognitive tasks and human baselines across multiple abilities. We use these as research framing; an education-only evaluation cannot establish broad general intelligence.

Anthropic distinguishes predefined workflows from model-directed agents and recommends increasing complexity only when task benefit justifies latency/cost ([Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)). Bounded product tools, checkpoints and outcome verification therefore precede wider autonomy. These sources do not select a model/provider or prove internal systems were replicated.
