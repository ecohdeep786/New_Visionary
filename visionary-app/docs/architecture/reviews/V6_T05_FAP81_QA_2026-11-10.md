# FAP-81 end-to-end QA receipt — the Community marquee honors Reduce Motion

Task: FAP-81 (epic FAP-69, V6 T05 Interaction, Motion & Feedback) · Candidate on `zcode/fap-81-reduced-motion-marquee` (base verified `origin/beta` @ `d4c50241` — the FAP-80 merge) · QA executed 2026-11-10 against the candidate dev server (localhost:5173) and the base checkout server (localhost:5174, beta `d4c50241`).

## Defect (T05 interaction/motion audit, recorded in Jira on the live product walk)

The product's motion law (`tokens.css`) says `prefers-reduced-motion: reduce` collapses motion to **static-and-visible**. The global contract in `index.css` enforces that with a universal selector and `!important` (`animation-duration: 0.01ms`, `animation-iteration-count: 1`, `transition-duration: 0.01ms`). A class selector carrying `!important` out-specifies the universal selector, so a component can silently opt out of the contract.

`/community`'s `PhotoMarquee` did exactly that: its inline `<style>` declared `animation: community-marquee-left 60s linear infinite !important` and the matching right-hand rule. Measured at beta `d4c50241` in Edge with `reducedMotion: 'reduce'`:

| measurement under `prefers-reduced-motion: reduce` | value |
| --- | --- |
| `matchMedia('(prefers-reduced-motion: reduce)').matches` | **true** |
| `document.getAnimations()` running | **2** |
| names / duration / iterations | `community-marquee-left`, `community-marquee-right` / `60s` / `infinite` |
| left-row transform, samples 1.4s apart | `-78.84px` → `-124.19px` (**45.35px moved**) |
| right-row transform, samples 1.4s apart | `-1865.16px` → `-1819.81px` (**45.35px moved**) |
| console errors | 0 |

The same sweep of 16 public routes under reduce found **only** `/community` running infinite animations; the other 15 routes reported 0. `qa-motion.mjs` enforced the curve/duration/bounce laws and that reduced-motion contract sheets exist, but it had no law preventing a per-component `!important` declaration from overriding the global collapse.

[Apple HIG — Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility): "People who are prone to these effects can turn on the Reduce Motion accessibility setting. When this setting is active, ensure your app or game responds by reducing automatic and repetitive animations, including zooming, scaling, and peripheral motion." … "Be cautious with fast-moving and blinking animations. When you use these effects in excess, it can be distracting, cause dizziness, and in some cases even result in epileptic episodes."

[Apple HIG — Motion](https://developer.apple.com/design/human-interface-guidelines/motion): "System components might also adjust their motion in response to factors like accessibility settings or different input methods." … "Add motion purposefully, supporting the experience without overshadowing it. Don't add motion for the sake of adding motion. Gratuitous or excessive animation can distract people and may make them feel disconnected or physically uncomfortable." … "Make motion optional. Not everyone can or wants to experience the motion in your app or game, so it's essential to avoid using it as the only way to communicate important information."

The marquee is decorative (`aria-hidden="true"`, empty `alt`), so the reduced-motion state has no informational content to preserve; the requirement is that the rows stay visible and still.

## 2. The change (three source files + enforcement)

- `frontend/src/pages/landing/CommunityPage.jsx`: removed `!important` from both marquee declarations and added a component-level `@media (prefers-reduced-motion: reduce) { .cm-left, .cm-right { animation: none; } }` guard. The rows keep their natural start position and remain fully visible; no `display:none`, `visibility:hidden` or `opacity:0`.
- `frontend/src/styles/tokens.css`: the motion-law comment now states the escape-hatch rule — no animation declaration may carry `!important` outside a `prefers-reduced-motion:reduce` block, because that out-specifies the universal reduced-motion kill.
- `frontend/scripts/qa-motion.mjs`: new Law 9 with two exported helpers. `reducedMotionBlockRanges()` maps `@media (prefers-reduced-motion: reduce)` blocks by brace matching (comment stripping is length-preserving). `reducedMotionEscapes()` reports animation/transition declarations carrying `!important` outside those blocks; the scanner emits `reduced-motion-escape` failures with exact file:line. It scans CSS sheets and JSX `<style>` templates / inline style objects through the existing extractors.
- No copy, flow, field geometry or data change. The marquee markup and duplicated photo tiles are untouched.

## 3. Contract tests (5 frontend tests + 3 motion-law unit tests)

`frontend/tests/fap81-reduced-motion-marquee.test.mjs` asserts: (1) both rows still declare the 60s linear infinite marquee when motion is allowed; (2) the component style block carries no `!important` at all; (3) an explicit reduce guard sets `animation:none` for both rows and does not hide them; (4) the extracted component stylesheet passes `reducedMotionEscapes`, while the pre-fix form (re-adding `!important`) is caught; (5) a repo-wide scan of every `src` JS/CSS file finds no animation/transition `!important` outside a reduce block.

`visionary-app/scripts/tests/motion-law.test.mjs` adds three unit tests: the pre-fix marquee is an escape and the guarded form is not; the law follows media-block nesting (a `transition !important` after a reduce block is still caught); JSX `<style>` templates, inline style objects and a guarded inline template are all covered.

`npm run qa:motion` scans 440 motion-bearing source files and holds; the two 60s marquee durations remain in the histogram.
