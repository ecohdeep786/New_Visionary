## Objective and method

Test supported browsers/devices, WCAG 2.2 AA, keyboard journeys, client security and recovery
states — without changing the approved UI. Method:

1. **Source and infrastructure inspection** — the release gate's existing coverage
   (keyboard-skip-link, keyboard-focus-visible, the F-10 accessibility-spot with alpha-composited
   contrast math and 44px control sizing that accounts for pseudo-element hit areas), the pinned
   recovery tests (`auth-errors`, `entity-recovery`, `learning-source-recovery`,
   `notification-recovery`, `portfolio-review-recovery`, `professional-career-recovery`), and the
   security header sets in `vite.config.js` (dev headers + the production CSP with
   `frame-ancestors 'none'`, self-pinned script-src and named hosts).
2. **Test baseline** — 36/36 recovery/auth-error tests pass before any harness work.
3. **Live harness** — new `frontend/scripts/a11y-security-review.mjs` covers what the release gate
   does not: keyboard journeys (first-Tab skip link, keyboard-only sign-in with a registered
   account, dialog focus trap), semantics (img alt, form labels, landmarks, per-route titles),
   client security (live headers, storage scan, reverse tabnabbing), recovery states (unknown
   routes), and devices (mobile 412×823, tablet 768×1024, desktop 1440×900 with overflow checks).
4. **Build determinism follow-up** — the battery's qa:perf caught a new flip immediately, which
   led to the F-27 fix generalization (F-28-F1).

## B. Findings

**F-28-F1 (P2 fixed, build determinism — generalizes the F-27 fix):** the battery's qa:perf caught
a fresh chunk flip on the first build of this lane: `homeCopy` merged away while
`learningCopy` (105,780 B) split out and `dailyPlanService` absorbed a module — the F-27
per-module pin (`organizationAuthorCopy` only) fixed one instance of a broader Rollup
shared-module nondeterminism. Generalized in `vite.config.js`: **every `src/lib/*Copy.js` module
(29 files) is pinned to a name-stable chunk** via the same manualChunks function — routes still
load only the copies they import, and the structure is deterministic. Verified: consecutive
builds hold exactly 153 chunks with identical per-name sizes (the only residual churn is internal
byte-order inside stable chunks — content hashes alternate, sizes and structure do not, so the
size-based budget law holds without re-record churn). Honest cost: the all-standalone shape
carries ~16 KB more gzip than the F-27 merged states (893,980 B vs 877,487 B — chunk wrapper
overhead of the extra standalone copies; route-level loading unchanged), recorded in the budget.

**F-28-F2 (P3, preview auth fixture — recorded, by design):** the preview repository's local auth
stores a **salted password hash** and a local session token in localStorage
(`visionary_users`/`visionary_sessions`). This is the recorded local-preview design: the product
copy bounds it explicitly ("This is a local preview, not verified cloud security"), no plaintext
password is stored (verified — the harness asserts the password string appears nowhere), and the
connected mode stores nothing client-side (the server owns the httpOnly session, F-24-F1). No
action; recorded so the reviewer sees the deliberate boundary.

**F-28-F3 (P2, carried from F-27 — still open):** the Lighthouse FAP-31 baseline regression on `/`
(target-size 0 on the landing carousel pager's overlapping `::after` hit-boxes) is unresolved —
it needs a pixel-verified redesign of the approved `ProgressDots` component in a UI-scoped lane.
Note: the release gate's own accessibility-spot does not flag it because that gate credits
pseudo-element hit-area extensions in its sizing math, while Lighthouse (and overlapping-target
attribution) does not.

**F-28-F4 (INFO, recovery posture):** the pinned recovery tests (36/36) plus the live unknown-route
check show the recovery states hold: surfaces render honest content, saved work is preserved, and
the auth error mapping (401/403/409/429, F-16-F2/F-3) remains pinned by tests. Live network-level
recovery (session expiry mid-use against a real backend) remains a hosted-acceptance dependency,
as recorded in prior lanes.

**F-28-F5 (INFO, environment):** the harness is deterministic on back-to-back runs (24/24 checks,
0 defects, 33 records, three consecutive runs after the navigation-hardening iterations). The
release gate ran against the preview-mode worktree dev server per F-24-F8.

**No product defects found in the live a11y/security surface. One build-config correction
(F-28-F1); no UI change.**
