## Defect (recorded during FAP-87, freshly reproduced on merged beta `ce2c391a`)

In an organization workspace, deep-linking the personal-learning routes `/dashboard/learn`, `/dashboard/practice`, `/dashboard/build` and `/dashboard/ask` rendered:

> **Permission required** — "Your Owner permission does not include this section. Ask the organization owner to review access."

Two falsehoods in one sentence:
1. For a fresh org account the viewer **is** the organization owner (`organizationPolicy` gives an org workspace without `organization_id` the owner profile), so the sentence is self-referential.
2. None of these routes are organization-workspace sections at all: `organizationPathAllowed` has **no capability** for them, so **no org profile — owner included — could ever grant them**. "Ask the organization owner" is a false promise for every role.

URL was kept (no rewrite — the FAP-75/87 law holds at gate 1); 0 console errors. Round-1 evidence: `t09-research-2026-11-11/t09-dashboard-research.json` (`roles.organization.cross[0..1]`); fresh before-probe: `research/t09-fap89-org-denials.json` (learn/practice/build/ask denials captured on 5174; people/analytics/audit/subscription/settings render normally for the Owner; 0 console errors across the sweep; screenshot `research/fap89-org-learn-denial-1440.png`).

## Root cause

`DashboardLayout.jsx` rendered a single denial branch for every `!organizationPathAllowed` route. The copy conflates two different reasons a route can be unavailable in an organization workspace:
- **capability** sections (people/cohorts/curriculum/library/analytics/audit/subscription) — gated by the viewer's administrative profile; "ask the organization owner" is correct here (and can only render for a non-owner profile, since the owner profile holds every capability);
- **personal** sections (learn/practice/build/ask/…) — not part of an organization workspace at all; the truthful message is that this section belongs to personal learning workspaces.

## Fix (3 files + tests)

- `src/services/organizationPolicy.js`: extracted the section maps to module constants and added an exported `organizationSectionKind(path)` helper (`'capability' | 'common' | 'personal'`). `organizationPathAllowed` now reads the same maps — **behavior identical** (verified by contract tests incl. owner-reaches-every-capability).
- `src/components/dashboard/DashboardLayout.jsx`: the denial branches by section kind. Capability denials keep the existing owner-directed copy and `{role}` interpolation; personal sections render an honest state — h1 **"Not available in this workspace"**, body **"This section belongs to personal learning workspaces. It is not part of an organization workspace."** — with the existing "Return to workspace" link. URL stays preserved in both cases.
- `src/lib/organizationCopy.js`: two new entries with hi and bn translations (en source is the key).
- `tests/fap89-org-denial-copy.test.mjs` (new, 5 tests): kind classification for personal/capability/common paths (incl. `class` detail and `guide`/`progress`/`career`), `organizationPathAllowed` semantics unchanged for owner + analyst profiles, owner-holds-every-capability law (so the owner-directed copy can never render for the Owner), DashboardLayout branching contract, and translation presence for all three locales.
