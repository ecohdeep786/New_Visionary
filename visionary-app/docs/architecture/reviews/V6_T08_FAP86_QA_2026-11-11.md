# FAP-86 end-to-end QA receipt — the toast shim stops forwarding store-only props to the DOM and its × control dismisses

Task: FAP-86 (epic FAP-69, V6 T08 Authentication, Onboarding & Trustworthy Forms) · Candidate on `zcode/fap-86-toast-shim-props` (base verified `origin/beta` @ `f6b34750` — the FAP-85 evidence commit) · QA executed 2026-11-11 against the candidate dev server (127.0.0.1:5173, worktree) and the base checkout server (127.0.0.1:5174, beta `f6b34750`). Edge (msedge channel), Playwright contexts, `--no-proxy-server`.

## Defect (T08 audit finding, filed as FAP-86)

The shadcn-style toast shim keeps two Radix-compat fields on every toast in the store (`use-toast.jsx` adds `open: true` and `onOpenChange`); `Toaster` spread the rest of each toast object straight into `<Toast {...props}>`, whose raw `<div>` received the camelCase handler. React warned **on every toast render**:

> Warning: Unknown event handler property `onOpenChange`. It will be ignored. at div at _c5 (…/src/components/ui/toast.jsx:75:41) …

Receipted real-product occurrence: the register "Code sent" toast in the FAP-70 before-capture (`t08-fap70-before-register.json`, beta 5174). The shim's `ToastClose` was additionally **dead** — no `onClick`, so × did nothing and a toast stayed visible until the store's 1,000,000 ms remove timer (verified live: still rendered after the click).

Why it matters: dev-console noise on every toast render (pollutes the console-error evidence later sweeps rely on) and a false-affordance close control.

This exercises the production store → Toaster → primitives path; it is not a mock.

## 2. The change (one consumer file; store and primitives byte-identical)

- `frontend/src/components/ui/toaster.jsx`: the mapped toast now destructures the two store fields out (`{ id, title, description, action, open = true, onOpenChange, ...props }`) so only DOM-safe props reach `<Toast {...props}>`; `open === false` hides the toast (the store's `dismiss()` sets it — the Radix semantic); `ToastClose` is wired `onClick={() => onOpenChange(false)}`, so × dismisses for real. A doc header records the law: all non-DOM handling lives in this consumer; `use-toast.jsx` and `toast.jsx` stay byte-identical.
- `integration/contracts/product-surface-review.json`: new review record for `frontend/src/components/ui/toaster.jsx` — the wired close made it an interactive control file, and the audit rejects unreviewed control files. Profile `client-widget-primitive` (same class as `ui/dropdown-menu.jsx`/`ui/toggle-group.jsx`: a UI primitive that delegates its action to the caller and grants no domain/server permission), followUp `SCOPE-06`, `ACCEPT-05`. Classification note: the audit's route-reachability is computed from declared route entries; App-shell imports (like `App.jsx`'s `<Toaster />`) land as `intentionally-unreleased` in the inventory — the same existing classification as its sibling `ui/toast.jsx`. The record matches the tool's computed reality; no exposed-capability claim is made or implied.
- Auto-removal timing (`TOAST_REMOVE_DELAY`) and all store behavior are intentionally unchanged.

## 3. Contract tests (3 new)

`frontend/tests/fap86-toast-shim-props.test.mjs` (3 tests): (1) `Toaster` destructures both store fields out of the mapped toast, hides on `open === false`, and spreads only DOM-safe props (no whole-toast spread); (2) `ToastClose` is wired to `onOpenChange(false)` and the store's `onOpenChange(false)` dismisses (byte-identical law); (3) regression guard: `ui/toast.jsx` never names `onOpenChange` or forwards a bare `open` prop.
