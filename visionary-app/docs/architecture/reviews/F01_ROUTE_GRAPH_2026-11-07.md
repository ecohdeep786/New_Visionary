## Defects found and fixed (all reproduced live before and after)

1. **F-01-D1 (P1, SEO/production truth):** `public/sitemap.xml` declared all 24 `<loc>` entries on `https://visionary.app` — the DNS-dead origin (F-31 recorded ENOTFOUND; live origin is `https://visionary.org.in`), and `public/robots.txt` pointed `Sitemap:` at the dead domain, so crawlers could not fetch the sitemap at all. Fixed both to the live origin. Regression: `tests/route-contract.test.mjs` asserts sitemap/robots origins equal the `SITE_URL` default and that the dead domain never reappears.
2. **F-01-D2 (P1, deep-link recovery):** signed-out deep links to protected routes (`/dashboard/learn`, `/onboarding`) rendered Login in place; after sign-in `safeReturnTo()` found no `?returnTo` and fell back to `/dashboard/home` — the intended destination was lost. Fixed `ProtectedRoute.jsx` to redirect unauthenticated access to `/login?returnTo=<pathname+search>` (destination now flows through the hardened validator: same-origin, dashboard-only, app-param stripping). Regression: source-law assertion in `route-contract.test.mjs`.
3. **F-01-D3 (P1, sign-in handoff race — found by live tracing):** even with `returnTo` preserved, sign-in STILL landed on `/dashboard/home`. History-stack instrumentation proved the two-step handoff race: the auth-state re-render `<Navigate to={authDestination(user)}>` navigated correctly to `/dashboard/learn` (consuming `?returnTo`), then `handlePasswordSubmit`'s `navigate(authDestination(profile))` re-resolved `safeReturnTo()` from the new URL, found no `returnTo`, and clobbered the destination with the default. Fixed `src/lib/authReturnTo.js`: the no-param fallback now resolves a current `/dashboard/*` path to itself, routed through the same app-param-stripping validation (security law preserved; open-redirect hardening unchanged). Regression: new test in `tests/workspace.test.mjs` covering the fallback, the app-param strip on the fallback, and the non-dashboard default.
4. **F-01-D4 (P3, inventory protocol):** product-surface inventory refreshed twice via the documented `npm run scope:audit:write` protocol after source changes (ProtectedRoute line shift; authReturnTo SHA update). Counts unchanged: 67 routes, 1651 control declarations, 236 control files.
