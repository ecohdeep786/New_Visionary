Task: FAP-78 (epic FAP-69, V6 T02 UX Research & Human Factors) · Candidate on `zcode/fap-78-classes-affordance` (base verified `origin/beta` @ `a245fb47` — the FAP-77 merge) · QA executed 2026-11-09 against the candidate dev server (localhost:5173) and the base checkout server (localhost:5174, beta `a245fb47`).

## Defect (T02 research walk, recorded in Jira on the live product walk)

A teacher with zero classes opened `/dashboard/classes` and met **two equal create controls on one screen**: the header "Create class" button (`TeacherHome.jsx:109`) and the empty-state "Create your first class" CTA (`TeacherHome.jsx:136–139`). Two equal weights for one intent make the user pause over which is "the" path. Creation itself already worked end-to-end (dialog fields Class name/Section/Subject/Room, submit → "Your class is ready." + class card + Open class) — the finding was affordance duplication only.

## 2. The change (one source file)

That single gate un-duplicates the empty state while returning the header control on every populated state. No copy changed (both labels resolve in en/hi/bn through the existing cascade — asserted at runtime in the test); no copy table touched. The `?create=1` deep link, the `CreateClassModal` render, `AssignLesson`'s zero-classes CTA and the student join flow are untouched (acceptance 2, asserted in the contract test and proven live by the create-flow probes and cross-role review).
