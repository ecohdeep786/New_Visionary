## Defect (T07 audit finding, filed as FAP-84)

`src/components/landing/CinematicHero.jsx` (the single-source hero used by the six trust/legal pages) passed the **camelCase `fetchPriority="high"`** prop to a raw `<img>`. React 18.2 does not recognize the camelCase img prop and logged on every load:

> Warning: React does not recognize the `fetchPriority` prop on a DOM element. If you intentionally want it to appear in the DOM as a custom attribute, spell it as lowercase `fetchpriority` instead.

Reproduced **6/6 in a fresh-context loop** at beta `07bfb77a` on `/research`, `/accessibility` and `/privacy` (and by the 21-route sweep on all six CinematicHero routes: `/research`, `/privacy`, `/terms`, `/security`, `/cookies`, `/accessibility`; stack: img → picture → CinematicHero). The receipted FAP-A4 treatment already existed: `LazyImage.jsx` destructures the camelCase caller prop and emits the standard lowercase `fetchpriority` content attribute, and `NewPersona.jsx` uses the `{...{ fetchpriority: "high" }}` passthrough on its raw imgs. `src/styles/apple-reference-notes.md` documented the leftover as outside the earlier correction.

Why it matters: the warning is dev-console noise on every load of the public hero, pollutes the console-error evidence later verification sweeps rely on (T13), and indicated the hero img was not on the receipted path.

## 6. Disclosed implementation fluke (fixed before any evidence was accepted)

The first implementation added a `{/* … */}` JSX **expression container** between the img's attributes (as an inline law note). That is invalid JSX in attribute position (containers are children-position syntax): esbuild failed to parse `CinematicHero.jsx` (vite internal server error, 130:85) and every CinematicHero route rendered the error boundary — so the **first after-sweep returned 0 warnings against broken pages**, which would have been invalid evidence. The comment was removed (the law lives in the doc header and the contract test, mirroring NewPersona's bare passthrough), the server recovered, and the shipped sweep is the valid one: 0 unrecognized-prop warnings **and** 0 error boundaries across all 21 routes, with the hero attribute verified present. Recorded here in full for auditability; nothing was hidden.
