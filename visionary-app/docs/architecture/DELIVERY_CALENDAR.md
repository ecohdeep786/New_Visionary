## When backend and ML change

Folder references are current ownership anchors; new modules/DTOs/repositories will be created inside them only during the corresponding implementation tasks. Existing folders are not replaced wholesale. The legacy gateway in `ml/upstream/` is not connected directly to the current product runtime. Qualified retrieval/generation components will connect through product-owned VATS/AIRA adapters; deliberate imported-source edits require provenance records. Contracts, tests and schemas lead.

**Current state:** the selected backend entrypoint connects account/auth/onboarding, test billing and feedback. It does not register the product ML workflow. Local VATS policy/binding tests are building blocks; they do not demonstrate a live AI teaching journey.

**Required before AI feature release:** frontend → authenticated backend with current UID/role/source permission checks → private VATS/AIRA workflow → eligible retrieval and evaluated model API (or a later qualified own model) → validated proposal → backend-owned saved state → frontend and authorized devices. AI teaching, Ask, Guide and AI Build features require this connected path and end-to-end acceptance before release.

**Why the legacy gateway is held back:** its caller identity, session ownership, private-response cache scope and deadlines still require product qualification. This temporary isolation does not remove ML from the launch architecture. Managed model APIs can power the launch through approved adapters; training our own model is a separate workstream. See [ML ownership and current gaps](../../ml/README.md) and [backend/ML authority](../../integration/VATS_CONTRACT.md).

## Calendar mechanics and limits

Jira field metadata confirms date-only Start date (`customfield_10015`) and Due date (`duedate`) for Task/Story/Bug/Epic. Native time-tracking is not listed in the available create-field metadata; estimated agent/founder hours are recorded in schedule notes instead of invented logged work. Atlassian documents how these dates schedule [calendar work items](https://support.atlassian.com/jira-software-cloud/docs/schedule-work-in-your-calendar/). This is the existing KAN board/project, not a separate Google Calendar.

The authenticated connector can verify stored fields. The in-app browser redirects to Atlassian login, so visual calendar rendering cannot be certified from that browser session. No credential entry, account change or security bypass is performed.

## Execution contract

A date never authorizes migrations, live billing, provider data transmission, deployment or a Later feature. Every owner follows the existing source/role/privacy/admission and release gates. Human/agent handoff is task requirement + current contracts + source anchors + acceptance evidence, with one current owning-store authority. Passing a date alone cannot change a user record, grade, consent or model version.
