## Corrections and actual behavior

The previous Map-based SQL simulator and duplicated five-table registry are replaced by a real Prisma/PostgreSQL adapter and the single reviewed DATA-01 SQL artifact. The baseline contains all ten domain tables, enum types, foreign keys and indexes. It is non-reversible. The former second migration which redundantly added existing fields and dropped baseline fields is removed; rollback tests use explicitly synthetic additive migrations instead.

The adapter verifies both actual PostgreSQL connections. Runtime must be the configured distinct role, lack schema/database CREATE, privileged role flags, migration-role membership and ownership of schema objects. Migration execution must use the configured non-superuser schema owner. Caller strings cannot establish identity. Runtime control-table mutation and metadata-sequence usage/update grants are also denied, including inherited/PUBLIC/default grants. The explicit runtime-role check is repeated inside the owning transaction before commit so newly created control tables cannot escape detection. SELECT-only control-table access is permitted. These checks correct an additional gap found by the separate reviewer after the first transaction-control correction. Artifact validation binds version, name, prerequisites, every up/down statement and reversibility. Applied and rolled-back history remains immutable against changed registry artifacts.

A schema-specific advisory transaction lock serializes runners. All pending DDL and append-only receipts commit in one transaction; a receipt failure rolls back SQL. Migration statement forms are restricted to transactional domain DDL and synthetic INSERTs: transaction/session/role control, CALL/DO and multi-command artifacts are rejected before DDL, including rollback artifacts. Empty and unsorted registries are refused. The separate reviewer found transaction-control escape and unsorted-registry defects in the first replacement; the corrected source adds actual PostgreSQL regression cases for both. Interrupted or ambiguously acknowledged commits are reconciled by durable ledger read-back on a new connection/process. Verification fingerprints actual table columns/defaults, constraints, indexes and enum values; physical drift blocks further apply/rollback. This is compatibility evidence for this schema, not a proof of all production client or query compatibility.

Any pending DDL or rollback over retained domain rows is denied. There is no boolean confirmation override. Only the newest explicitly reversible migration can be rolled back; the canonical baseline cannot. No nontransactional migration facility is provided.

Backfills persist run definition, cursor, per-key payload digest and checkpoint in PostgreSQL. Each page's database writer, deduplication receipts and checkpoint share a transaction. Concurrent runs serialize; stable duplicate keys skip the actual writer, while changed payload/definition is refused. Row/page/batch/time budgets, cursor progress/cycles and cancellation are checked. A bounded invocation returns done=false when resumable work remains. The writer must use the provided transaction; external provider calls or side effects are outside this guarantee and are not authorized by the API. Sources must supply stable pages and a versioned immutable definition.
