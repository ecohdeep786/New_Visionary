## Internal design status

The previous shell had a weak first-use hierarchy and a hard-to-discover voice control. The current pass improved role-aware search wording/shortcut, outlined navigation, five role Home priority panels, and Learn/Practice/Build introductions. Build has an illustrated empty state. The Guide control now opens a panel for Boy/Girl animated visual choice, actual audio status/toggle, text fallback and close. Opening it creates no learning evidence; reduced motion freezes decorative animation. [Student Home](baseline/design-2026-09-27/student-home-1440.png), [Learn desktop](baseline/design-2026-09-27/student-learn-1440.png), [Build mobile](baseline/design-2026-09-27/student-build-390.png), [Boy panel](baseline/design-2026-09-27/voice-boy-1440.png), [Girl mobile panel](baseline/design-2026-09-27/voice-girl-390.png).

Design rules for remaining work: show one main task and a clear primary action; keep source, saved, audio and sharing states explicit; use existing blue/white tokens and decorative illustrations that carry no essential meaning; label icon controls and preserve keyboard/text fallback; support reduced motion and 390px layouts; verify empty, populated, loading, error, denied and interrupted states. Never imply real AGI or invent progress.

**Design acceptance remains open.** The first Ask composer, authored learning unit and populated Build editor now have desktop/intermediate/mobile captures; the learning stage indicator is clearer, and voice-to-text fallback closes its panel. Inspect failure states, Build sharing and role tools. Verify keyboard beyond the Ask focus path, screen reader, 200% zoom, Hindi/Bengali and long text, youngest-tier readability, seven widths and live microphone permission paths. Continue fixes alongside the authorized local M2 work before the product-preview gate.
