# Visionary internal product: launch sequence and resume point

Updated 2026-09-26. This is the execution checklist for the existing internal app, not a claim that artificial general intelligence exists today. Preserve the blue/white shell, existing routes and local work. Do not modify public marketing pages or the frontend team's separate folder as part of this sequence.

## Product contract

One person may hold multiple isolated roles. Student, teacher, parent, professional and organization use the same identity, content, cognition, evidence, memory and interaction-event services with different authorized views. The four permanent work areas are Learn, Ask, Practice and Build. Home chooses one evidence-backed next step, not a feature grid. A connected class or organization can add work to a learner's day without taking ownership of private learning. Native-language text works first; voice is optional and permission-based. Never claim live AGI, official coverage, cloud sync or verified child consent before those systems exist.

## Connection rule

Adapters are replaceable at the service boundary, never by making components fetch raw collections. Server authorization must repeat every client-side role/consent check. L7 logs schema and outcome, not prompt text or personal identifiers. The server must be able to reject a model reply, revoked access or stale workspace even if the UI previously allowed it. Model outputs propose actions; consequential writes require an explicit user confirmation. An unconnected or uncertain answer is visibly unconnected or uncertain.
