# Visionary frontend

Existing React/Vite public site and five-role internal workspace. Source is in `src/`, assets/fonts in `public/`, service regressions in `tests/`, and rendered-review scripts in `scripts/`. Vite, TypeScript, Tailwind, ESLint, package and lock files are owned by this directory.

From the product root use `npm run dev`, `npm run build`, `npm run lint`, `npm run typecheck` and `npm test`. From here use the same commands directly. Install with `npm ci` here or `npm run frontend:install` from the root. Output is `frontend/dist/` from the product root.

The `@/` alias still refers to `src/`; public URLs and `/src/` development module URLs are unchanged. Page/component/service/domain structure, typography and role journeys are retained. Test imports remain relative to this package. Local preview records are not migrated by relocation.

Browser-review tasks are `qa:navigation`, `qa:fonts` and `qa:design`; root equivalents begin with `frontend:qa:`. Evidence paths resolve to product documentation independently of the working directory. These are bounded historical harnesses; account/session and wider human/device acceptance remain separately recorded.

Read [the product domain map](../docs/architecture/PRODUCT_DOMAINS.md), [the internal handoff](../docs/visionary/README.md) and [integration gaps](../integration/CONTRACT_GAPS.md) before connecting live services.

Firebase Web SDK13.0.0 is connected when ignored `.env.local` sets `VITE_AUTH_MODE=firebase` (template `.env.firebase.example`). `src/api/firebase/` uses in-memory Firebase identity and server-owned sessions/profiles. Login/register resume onboarding or the dashboard from saved Firestore state; email registration uses a verification link. Analytics remains disabled. Run the standalone auth server and open `http://localhost:5173`; Vite proxies `/api`. Read [the auth contract](../integration/FIREBASE_AUTH_CONTRACT.md) for boundaries: learning services remain local and provider/guardian/deployment acceptance is incomplete. `node scripts/firebase-auth-review.mjs` is an offline browser-fixture routing review with a running dev server.

D-064 adds human-facing error mapping, duplicate-submit protection, password-policy guidance, verified reset/verification action pages, recovery from session cleanup failures, fixed-project email handling and a stable auth context for development hot reload. `scripts/auth-emulator-review.mjs` runs the complete demo-only SDK workflow with the isolated backend memory harness; `scripts/auth-hmr-review.mjs` checks the provider update without changing source bytes or signing into production. See the contract's isolated-review section before starting those services. Default live email templates/handlers are not changed by these frontend fixes.

D-066 introduces concise product setup and the illustrated three-screen welcome dialog. Questions/screen rationale: docs/architecture/discussions/product-onboarding-journey.md. Current browser review: node frontend/scripts/product-onboarding-review.mjs (onboarding-review.mjs delegates to it). Richer D-065 fixture evidence remains historical. Existing completed Firebase accounts are preserved; open Show getting started after signing in to review the new introduction.

D-067 adopts authenticated mutation responses directly, coalesces overlapping profile reads and bounds transport retries/deadlines. `node scripts/auth-font-handoff-review.mjs` (from this directory with the normal dev server running) checks five fictional API scenes, actual locally rendered Google Sans glyphs, safe read recovery, trusted activity refresh and the clean dashboard header. It never signs into a live account. Payment identity/authority boundaries are recorded in [the payment handoff](../integration/PAYMENTS_AUTH_HANDOFF.md).

D-069 connects public paid-plan/interval intent through sign-in/registration/setup to the routed Plans page. Firebase mode uses authenticated server billing, explicit recurring review, Razorpay Standard Checkout, verified payment status, renewal cancellation, account-scoped Family benefits and printable test invoices. Local-preview mode retains its existing simulation. Billing reads do not extend idle sessions. Read [the payment contract](../integration/PAYMENTS_CONTRACT.md); the normal browser review is `node frontend/scripts/payment-review.mjs` from the product root, with an optional `--razorpay-test` provider run. All current billing is test-only; live taxes, usage/model enforcement and organization contracts are separate release work.
